Inside the JavaScript Engine

Understanding V8, SpiderMonkey, and Asynchronous Execution

The General Workflow

To understand why JavaScript is fast, we look at the internal pipeline engines use to turn text into machine action:

  • Parsing: Code is turned into an Abstract Syntax Tree (AST).
  • Compilation: A "Baseline Compiler" quickly turns AST into Bytecode.
  • Execution: The engine runs bytecode immediately.
  • Optimization: A "Profiler" watches for "hot code" and optimizes it into Machine Code.

Engine Comparison

1. V8 (Chrome / Node.js)

Uses Ignition (Interpreter) for fast startup and TurboFan (Optimizing Compiler) for high performance.

Example: If add(a, b) always uses numbers, TurboFan generates specific machine code for numbers.

2. SpiderMonkey (Firefox)

The first JS engine. Uses a multi-tier strategy: Baseline Interpreter → Baseline Compiler → IonMonkey (Deep Optimizer).

The Environment

Execution Context

The "box" containing variables and code. There are two types: Global and Function contexts.

Call Stack (LIFO)

Tracks where we are in the script. Last In, First Out.

const a = 10;
const first = () => {
  second();
  console.log("Hello I am first");
};
const second = () => {
  third();
};
// Execution order: first -> second -> third

Concurrency Model

Single-threaded: Like a chef with one burner. One command at a time.

Synchronous

Every line waits for the previous one. If a line is slow, the app "freezes."

Asynchronous

Start a task and move on. When finished, the engine notifies the program.

console.log("Start");
setTimeout(() => console.log("Async Task"), 3000);
console.log("End");

Promises

"Think of it like ordering a pizza: you receive a receipt (the Promise). The pizza is Pending. Eventually, it is Fulfilled (delivered) or Rejected (out of ingredients)."

Async / Await

Syntactic sugar for Promises, making code look synchronous and readable.

const loadData = async () => {
    try {
        const response = await fetch('url');
        const data = await response.json();
    } catch (err) {
        console.log(err);
    }
}

The Event Loop

The Event Loop's job: If the Call Stack is empty, take the first task from the Callback Queue and push it onto the Stack.
